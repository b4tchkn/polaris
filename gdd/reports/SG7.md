# サブゴール完了報告：SG7 シミュレーション1の学びを GDD 本体に反映する

## 何が出来たか、どう触るか

- `state.md` の学びは `gdd-init` で別のリポジトリを始めると引き継がれない。どの題材でも効く学びを、`gdd-loop` の手順と雛形に移した。
- 移したもの（人間が選んだ4つ）：
  - 作ったものは本来の起動方法で確かめる → `gdd-loop` の 3
  - 外のデータは決める前に実データで試す → `gdd-loop` の 3
  - 人間の指示を反映する前に、解釈が分かれる点を3案で選んでもらう → `gdd-loop` の 2
  - （人間の追加指示）サブゴールに評価基準（定量 / 定性）を置き、報告でその基準で振り返る → `gdd-loop` の 5、`subgoals.md` と `report.md` の雛形、design.md 3
- SG6 で採用した仕組みの修正も入れた：AI が出す案にはいつもトレードオフを書く（改善の提案にもトレードオフの列）、案を選んだら毎回理由を聞いて人間の言葉で `adr.md` に残す。
- 移さなかったもの：朝の skill に固有の学び（Slack・GitHub・JIRA・会話ログの扱い）、この環境に固有の学び（push、Bash の書き方、用語）。「わかりにくい言葉を使わない」は手順 6 にすでにある。
- デモ：`git diff -- .claude docs`。この報告が新しい雛形（評価基準での振り返り、トレードオフの列、評価基準付きの3案）で書いた最初の報告。

## 一番自信がない判断

- 評価基準を、作る系・決める系の両方で毎回必須にしたこと。決める系では「人間が合意できる」以外の基準が書きにくく、形だけの行になるかもしれない。

## 捨てた案

- 評価基準を完了条件の中に書く・定量だけにする：人間が A（独立した行）を選んだ（`adr.md`）。
