# サブゴール完了報告：SG6 シミュレーション1（朝の振り返り skill）を動くところまで回す

## 何が出来たか、どう触るか

- `simulations/morning-review/`（commit しない）で、GDD を SG0〜SG3 まで回した。
  - SG0 届くメッセージの形を決める → SG1 カレンダーだけで Slack に届く → SG2 GitHub と Slack でやり残し → SG3 作業履歴・JIRA・Confluence。
  - できた skill は、6つの集める先から昨日の振り返り・やり残し・今日まずやることをまとめ、Slack の自分宛てに送る。人間が `/morning-review` で起動して確かめた。
- シミュレーションの中で、人間の判断は15回（ゴール決め1、各サブゴールの判断4、途中で止まって聞いた判断3、次のサブゴールの選択3、改善の提案の採否4）。案から選んだ判断は `simulations/morning-review/gdd/adr.md` に6件残った。
- シミュレーションから GDD 本体に入った変更：案はいつも3つ（トレードオフ付き）、選んだ理由を adr.md に残す、判断は AskUserQuestion で選ぶ、ゴールが雛形のままなら一緒に決める、CLAUDE.md に最小限・YAGNI、学び4つ（本来の起動方法で確かめる、完了条件のデータを先に確かめる、など）。
- デモ：`simulations/morning-review/gdd/` の報告一式（SG0〜SG3）と adr.md。

## 一番自信がない判断

- 「実際の朝に使って直す」をやらずにシミュレーションを終えたこと。受け入れシナリオ4（数分で最初の1つを決められる）は確かめていない。GDD の仕組みの検証としては足りているが、作ったものが本当に役立つかはわからない。

## 捨てた案

- シミュレーションの中で GDD 本体を直さず、終わってからまとめて直す：人間がその場で仕組みの修正を指示したので、その場で直した。
