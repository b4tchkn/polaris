## 2026-10-06 SG6 完了時：次のサブゴール

- 何を決めたか：SG6 のあと、次に何をやるか
- 出した案：
  - A SG7 シミュレーション1の学びを本体に反映する：予定どおり。まだ1題材分の学びだけ
  - B 別の題材でシミュレーション2を回す：偏った学びを見分けられる。反映は後回し
  - C 既存のリポジトリに導入する（前倒し）：受け入れシナリオ2に早く届く。0→1 の学びは固まらないまま
- 選んだ案：A
- 理由：予定どおり学びを仕組みに固める（選択肢の説明から）

## 2026-10-06 SG7 評価基準の入れ方

- 何を決めたか：「サブゴールを決めるときに評価基準を決め、完了報告でその基準で振り返る」（人間の追加指示）をどの形で入れるか
- 出した案：
  - A 評価基準を独立した行にし、報告に「基準 / 結果 / 達成したか」の表を足す：判断材料が一番はっきりする。表が1行・1節増える
  - B 完了条件の中に書く：変更は最小。完了条件と混ざって見分けにくい
  - C 定量の基準だけにする：判断がぶれない。決める系は数字にしにくい
- 選んだ案：A
- 理由：判断材料をはっきりさせたい

## 2026-10-06 SG7 完了時：polaris の配り方

- 何を決めたか：誰でも polaris を入れて GDD を始められるようにする配り方
- 出した案：
  - A plugin だけ（polaris リポジトリ自体をマーケットプレイスにする）：配る形と直す場所が1つ。受け入れシナリオ5（Template として公開）を書き換える
  - B plugin と Template Repository の両方：新規の人は Template から1クリック。エンジンが2か所に入り二重保守
  - C A に加えて Anthropic の公式ディレクトリに申請：見つけてもらいやすい。審査があり、先に A が要る
- 選んだ案：A
- 理由：新規でも既存でも同じ手順にしたい

## 2026-10-06 SG7 完了時：次のサブゴール

- 何を決めたか：配り方を plugin に決めたうえで、次に何をやるか
- 出した案：
  - A SG8 polaris を plugin にする：配る土台ができる。polaris 自身の開発のしかたも plugin 前提に変わる
  - B 先に既存リポジトリへ .claude/ をコピーして試す：1→100 の学びが早い。コピー分はあとで捨てる
  - C plugin 化と既存リポジトリへの導入を1つのサブゴールでやる：一番早い。大きく、外れたとき捨てる量が多い
- 選んだ案：A
- 理由：配る土台を先に作りたい

## 2026-10-06 SG8 エンジンの置き場所

- 何を決めたか：plugin にするとき、エンジン（gdd-init / gdd-loop の skill、雛形、hook）をリポジトリのどこに置くか
- 出した案：
  - A リポジトリの直下をそのまま plugin にする：一番単純。polaris 自身の gdd/ や docs/ も配られる
  - B plugins/polaris/ に移す：エンジンだけが配られる。polaris の開発は --plugin-dir で起動する
  - C .claude/ に残し、配る用にコピーする：開発のしかたは今のまま。エンジンが2か所になる
- 選んだ案：B
- 理由：配るものだけを配りたい

## 2026-10-06 SG8 plugin の言語

- 何を決めたか：plugin のどこまでを英語にするか（人間の指示「基本的に英語で plugin を作る」の範囲）
- 出した案：
  - A 配るものを全部英語にする：統一される。雛形も英語なので、日本語で使いたい人には合わない
  - B 説明文と README だけ英語：変更は小さい。skill の中身が読めない人には使いにくい
  - C 全部英語にし、報告や質問は使う人の言語で出す：誰でも使えて日本語でも返る。翻訳の量が一番多い
- 選んだ案：C
- 理由：誰でも使えるようにしたい
