# サブゴールレビュー：SG9 機械的な停止条件を実装する

## 何が出来たか、どう触るか

- `plugins/polaris/hooks/guard-gdd-writes.sh` を、正規表現で Bash コマンドを見る方式から「ツール実行の前に `gdd/` の状態ファイルを控え、実行後に結果を比べて戻す」方式に置き換えた。Bash / Edit / Write の PreToolUse と PostToolUse で動く。止めるのは4つ：
  - `gdd/goal.md` / `gdd/subgoals.md` が Bash で変わった・作られた・消された → 元に戻して exit 2
  - `gdd/state.md` の「学び」（`Learnings` / `学び` 見出し下の行）が消えた → 元に戻して exit 2
  - `gdd/adr.md` が追記以外で変わった → 元に戻して exit 2
  - テストファイルに skip / ignore 系のマーカーが増えた → exit 2（戻さず、人間に3案で聞くよう指示）
- `gdd-init` が書く ask ルールに、戻せない行為を足した（依存の追加、マイグレーション、`git push` / PR マージ / release、履歴の書き換え、`.claude/settings.json` の変更）。約30行。
- README の hook と承認ルールの説明を書き直し、design.md 7 に「機械化できたもの / まだ指示文だけのもの」の対応を1段落足した。
- `tests/guard-gdd-writes.sh`：hook に本物と同じ形の JSON を流す自己テスト。20 ケース（Bash 書き込み 10 経路、新規作成、読むだけ、学びの削除 / 維持 / 日本語見出し、adr の追記 / 書き換え、テストの skip 追加 / 変化なし、テスト以外、新規ファイル）。
- デモ：`bash tests/guard-gdd-writes.sh`（20 PASS）。`--plugin-dir plugins/polaris` で起動したセッションで `echo x > gdd/goal.md` を実行すると元に戻って「Edit ツールを使え」と返る。hook の実行時間はこのリポジトリで pre＋post 合わせて 0.22 秒。

## 一番自信がない判断

- 学びの検査を「古い行の文字列が新しいファイルのどこかに含まれていること」にしたこと。`gdd-loop` の手順4は「重複の統合はよい」と書いているが、統合で元の文を消すとこの hook が戻してしまう。手順と hook が食い違っているので、手順側を「元の行は残して統合した行を足す」に直す提案を出した（改善の提案1）。
- 人間は「design.md 7 の項目は全部機械的に止めたい」と言ったが、外部サービスの選定・課金・認証はファイルやコマンドの形で見分けられず、指示文のまま残っている。

## 捨てた案

- 正規表現のブロックリストを増やす：敵対的レビューで 25 経路中 6 しか止まらず、構造的に負ける。
- `git HEAD` を基準に差分を見る：Edit ツールで承認済みの未コミット変更まで巻き戻してしまう。実行前の控えを基準にした。
- `jq` を使う：前回の判断（09e7e1a）どおり使わない。`sed` で `tool_name` / `session_id` / `file_path` だけ取る。
