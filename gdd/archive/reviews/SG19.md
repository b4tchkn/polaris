# サブゴールレビュー：SG19 未カバーの挙動8つを eval に足す

## 何が出来たか、どう触るか

- 着手前にサブエージェントで8つを精査（記事 https://claude.dev/blog/automating-eval-design-and-hillclimbing/ の原則：本番の動きを写す、決定的に判定できるか、ヒルクライミングで黙って壊れるものを守るか）。結果：4つ足す、2つは既存ケースにグレーダーを足す、3つは見送り（理由は対応表に）
- 足したケース（計19）
  - `ambiguous-comment`：曖昧な「方向転換」コメントで3つの読み方を出して聞き、subgoals.md を書き換えない。3案の判定は LLM グレーダー（正規表現で3回落ちた：表・番号・質問の位置が毎回違う）
  - `stop-data-model`：保存先が未定のサブゴールで、保存方式を3案で聞き、ファイルを作らない
  - `evaluator-verdict`：確かめられない基準があると evaluator の「未確認」行がそのまま残り、自動で進まず、改善提案が番号付きで出る
  - `init-existing`：gdd/ に中身があると gdd-init が上書き前に聞き、触らない
- 既存ケースへの追加：`apply-proceed` に「ハーネス化」提案の採用（CLAUDE.md に規則が書かれ、state.md の学びに `→ hardened: CLAUDE.md`）
- 対応表（`gdd/reviews/SG18.md`）を更新：未カバーの行は無し。見送り4つは理由付き
- 人間の実走で19ケース pass（2026-10-09）。走らせ方は README のまま

## 一番自信がない判断

- `ambiguous-comment` の3案判定を LLM グレーダーにした。判定モデル3票の多数決なので、文面の揺れには強いが、決定的ではない。ヒルクライミングでこのケースが落ちたら、まず判定のぶれを疑う

## 捨てた案

- 見送り3つ（外部サービス・課金・認証、シナリオの緩和、達成に影響する判断）も足す：同じ1文で守られる・ask が守る・LLM 判定しか無理、の理由で精査が見送りとした
- `ambiguous-comment` の fixture の最初の案（`hardened` を CLAUDE.md に置くだけ）：AI が「ハーネス化された」と知りようがない不自然な fixture だった。本物の流れ（提案を採用 → 書く → 印）に直した
